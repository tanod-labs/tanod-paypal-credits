# PayPal-funded tools for AI agents

**Project name:** Pay-per-call tools for AI agents, funded with PayPal

**Elevator pitch:** An AI agent requests tool credit, a human approves a PayPal sandbox checkout, and the agent resumes paid sample calls. Open source (MIT); local demo credits, not live funds.

## Inspiration

An agent should not need control of a person's payment account to use paid tools. We built a small example in which the agent requests credit, the human approves the purchase, and the agent resumes from a prepaid balance.

## What it does

An open-source (MIT) MCP server exposes four tools: check the local balance, try a paid sample call, request a PayPal top-up, and resume after approval. With no credit, the sample refuses without a deduction. The agent returns a PayPal approval link; the human authorizes the sandbox purchase; the server captures it and adds credit only after validating the completed capture. A repeated resume does not add credit twice.

The example credits USD 1.00 locally after a matching sandbox capture. The deterministic sample tool then deducts USD 0.001 for an answer, leaving USD 0.999. The sample answer is not generated by AI: an AI client is the caller, using the MCP tools to coordinate the approval-and-resume flow.

## What is real, and what is sandbox

The integration makes actual calls to PayPal's sandbox OAuth and Orders v2 APIs when configured with a sandbox app. Sandbox payments are test money. Offline tests instead use a fake PayPal transport; they are not proof of a completed buyer checkout.

This repository does not call Tanod's hosted tools. Its local demo keys and balances cannot be spent at tanod.dev. The [live credits offer](https://tanod.dev/v1/credits/packs) currently advertises x402 funding, not PayPal/card funding; the [credits page](https://tanod.dev/credits/) explains HTTP and MCP use and answer-only charges. The demo's sandbox pack is an example, not a live Tanod offer.

## How we built it

Python 3.11+, standard library, SQLite and MCP JSON-RPC over stdio. PayPal is central: order creation, human approval and a completed capture gate the local credit. Capture retries use the same request ID. The ledger checks the capture's status, amount, currency, custom ID and capture ID before crediting an order once. Six offline tests exercise approval gating, repeated resume, mismatches and restart boundaries.

## Challenges and learning

An order, buyer approval and a completed capture are different states. The agent must wait rather than invent success. The tools return explicit next steps; the same MCP server process must stay open from order creation through capture. This is an educational sandbox example, not a production checkout or refund service.
